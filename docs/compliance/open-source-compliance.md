# 第三方开源项目使用边界

## 基本原则

参赛作品应以团队在本届比赛期间完成的原创设计和实现为主体。开源项目可以作为技术调研对象，也可以使用合规的通用开源库，但不建议直接 fork 或拼接完整项目作为参赛作品。

## 推荐做法

- 可以参考多个开源项目的系统架构、模块划分、Agent 角色设计、RAG 流程、知识图谱建模方法和部署方式。
- 可以使用通用框架和库，例如 `React`、`Vue`、`Next.js`、`FastAPI`、`Spring Boot`、`LangChain`、`LangGraph`、`Chroma`、`PostgreSQL`、`Redis`。
- 可以阅读开源项目代码理解工程组织方式，但核心业务逻辑、前后端页面、接口设计、数据库设计、Agent 编排和文档应自主实现。
- 应在作品文档中列出使用的第三方依赖、协议、链接和用途。

## 高风险做法

- 直接复制某个开源项目的核心代码作为参赛主体。
- fork 一个完整学习平台项目，改名称、改 UI、改少量功能后提交。
- 将多个开源项目的代码片段拼接成作品，却不说明来源。
- 删除原作者版权声明、license 或 NOTICE。
- 使用无 license 的 GitHub 代码进入项目。
- 使用 `AGPL-3.0` / `GPL-3.0` 项目的代码进入核心项目，而不愿意承担相同协议开源义务。

## 文档披露模板

```md
## 第三方开源依赖说明

本项目技术路线参考了开源社区中常见的 RAG、Knowledge Graph 和 Multi-Agent 教育应用架构。项目核心业务流程、数据库设计、Agent 编排逻辑、前端界面、后端接口和演示数据均由参赛团队自主设计与实现。

本项目使用以下开源依赖作为基础设施：

- React, MIT License, 用于前端界面开发
- FastAPI, MIT License, 用于后端 API 服务
- LangChain, MIT License, 用于大模型应用编排
- Chroma, Apache-2.0 License, 用于向量检索
- PostgreSQL, PostgreSQL License, 用于业务数据存储

上述依赖仅提供通用技术能力，不构成参赛作品的主体实现。
```
