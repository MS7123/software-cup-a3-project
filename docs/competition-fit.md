## 1. A3 赛题关键要求摘要

- 赛题名称：基于大模型的个性化资源生成与学习多智能体系统开发。
- 组类：A组；出题企业：科大讯飞股份有限公司。
- 业务目标：面向高等教育个性化学习，构建能够满足学生差异化学习需求的智能学习系统。
- 核心场景：以某一具体高校专业课程为切入点，依托课程资源，为学生生成个性化、多模态学习内容。
- 基本功能：
  - 通过自然语言对话构建动态学生画像，画像不少于 6 个维度，并支持随学习过程更新。
  - 体现 `Multi-Agent` 架构，由不同角色智能体协作完成资源生成。
  - 至少生成 5 种个性化学习资源，例如课程讲解文档、思维导图、练习题、拓展阅读、多模态视频/动画、代码实操案例等。
  - 根据学生画像、学习进度、知识掌握情况和学习偏好规划个性化学习路径，并进行资源推送。
  - 智能辅导和学习效果评估属于可选加分项。
- 非功能要求：
  - 界面简洁清晰，符合现代 AI 产品交互习惯。
  - 标注开源项目、AI 工具和依赖来源及协议。
  - 具备防幻觉和内容安全过滤机制。
  - 关键智能体能力响应时间合理；长任务应有进度追踪或流式呈现。
- 数据与提交：
  - 参赛团队需自行构造至少一门完整高校专业课程的初始知识库或文档集。
  - 初赛提交包括演示 PPT、可运行多智能体相关文件、7 分钟以内演示视频、配套文档。
  - 如使用 AI Coding 工具，需要给出相关说明。
- 评分占比：
  - 创新价值与实用性：35%。
  - 功能实现及技术要求：45%。
  - 配套文档丰富度：10%。
  - 演示视频、PPT 效果：10%。

## 2. 当前项目已符合的点

- 项目方向已对齐 A3：面向大学课程学习的个性化资源生成与学习多智能体系统。
- 演示课程已冻结为数据结构，满足“以某一具体专业课程为切入点”的要求。
- 已有学生端主闭环：画像、学习路径、资源生成、Tutor、Quiz、Evaluator、Agent trace。
- 已有 3 个模拟学生画像：基础薄弱型、考试冲刺型、算法实践型。
- 已有 `Multi-Agent` 分工设计和执行摘要记录，覆盖 Planner、Resource、Tutor、Quiz、Evaluator。
- 已有数据结构 MVP 知识点范围：复杂度分析、链表、栈/队列、二叉树遍历、BFS/DFS。
- 已有本地演示与验证基础：前后端工程、demo data、本地运行配置、基础 smoke 验证。
- 已有开源合规边界文档。
- 已有 Tutor Agent 的真实 LLM 最小接入与 rule-based fallback。

## 3. 当前项目不符合或不足的点

- 学生画像目前是固定模拟画像，尚未满足“通过自然语言对话自主构建画像”的比赛要求。
- 画像维度需要明确达到不少于 6 个，并支持随学习过程更新。
- 资源生成类型需要扩展到至少 5 类；当前资源类型仍偏 MVP。
- 多模态资源不足，视频/动画可以先以脚本、分镜或卡片化方案作为轻量呈现。
- 真实 RAG / 知识库检索仍不完整，课程资料来源引用和防幻觉能力需要加强。
- 学习效果评估已有最小闭环，但还需更清楚地展示薄弱点、掌握度变化和资源调整。
- 开源依赖 license 清单、AI Coding 工具使用说明、系统开发说明书、测试说明书仍需补齐。
- 演示材料尚未形成 7 分钟以内视频脚本和 PPT 主线。

## 4. Phase 1 冻结范围

### 演示课程

数据结构。

第一阶段知识点范围冻结为：

- 复杂度分析
- 链表
- 栈/队列
- 二叉树遍历
- BFS/DFS

### 用户范围

第一阶段只做学生端。

不做教师端、管理端、班级管理、真实学校数据接入。

### 主流程

冻结主流程：

```text
学生画像
-> 学习目标
-> 学习路径规划
-> 个性化资源生成
-> Tutor 问答
-> Quiz 测验
-> Evaluator 评价
-> Agent trace 摘要展示
```

`Agent trace` 展示摘要即可，包含 Agent 名称、调用顺序、输入摘要、输出摘要、状态和关键决策依据；不要求展示完整 prompt 或完整输入输出。

### 必做功能

- 数据结构课程的初始知识库或模拟课程资料。
- 至少 3 个学生画像样例：基础薄弱型、考试冲刺型、算法实践型。
- 学生画像维度补齐到不少于 6 个。
- `Multi-Agent` 协作流程可展示。
- 学习路径规划。
- 至少 5 类资源生成。
- Tutor 问答。
- Quiz 生成与作答。
- Evaluator 学习效果反馈。
- 资料来源引用或依据说明。
- 防幻觉基础策略：资料不足时不编造、标注不确定性、fallback 可用。
- 7 分钟演示主线可跑通。
- 开源依赖、AI 工具和 AI Coding 使用说明。

### 加分功能

- 智能辅导体验增强：多轮问答、基于学生画像调整讲解风格。
- 学习效果评估增强：掌握度变化、薄弱点定位、后续资源推荐。
- 多模态资源展示：思维导图、代码实操案例、视频/动画脚本或分镜。
- Agent trace 可视化时间线。
- 生成进度追踪或流式呈现。

### 暂不做功能

- 教师端和管理端。
- 真实学校账号、真实学生隐私数据和校内系统对接。
- 覆盖完整数据结构课程全部章节。
- 生产级部署、分布式任务队列和复杂运维。
- 重型知识图谱平台、复杂在线协同编辑器。
- 修改已 Accepted 的架构基线。
- 新增技术方案或替换现有技术栈。

## 5. Phase 2 到 Phase 5 开发优先级建议

### Phase 2：核心智能能力完善

优先级：

1. 对话式学生画像构建，补齐不少于 6 个画像维度。
2. 资源生成扩展到至少 5 类。
3. 真实 RAG 最小闭环：资料解析、chunk、检索、来源引用。
4. Tutor / Resource 的真实 LLM 能力稳定化，并保留 fallback。
5. Evaluator 输出薄弱点、掌握度变化和下一步学习调整。

### Phase 3：演示体验优化

优先级：

1. 把主流程压缩成评委能看懂的一条演示线。
2. Agent trace 做成清晰时间线或流程摘要。
3. 优化资源卡片、测验反馈、掌握度变化展示。
4. 补 loading、error、fallback、空状态。
5. 准备 7 分钟演示脚本初稿。

### Phase 4：稳定性与交付

优先级：

1. 一键启动和一键验证。
2. demo data 重置。
3. 主流程 smoke test。
4. 依赖和 license 清单。
5. AI 工具、AI Coding 使用说明。
6. 无 API key 时 fallback 可演示。

### Phase 5：比赛材料

优先级：

1. PPT：价值、赛题对齐、系统主线、核心功能、创新点。
2. 7 分钟演示视频脚本和录制。
3. 系统开发说明书。
4. 测试说明书。
5. 赛题要求对应表。
6. 开源合规与 AI 工具使用说明。

## 6. Phase 1 结论

当前项目主线继续冻结为：

> 面向数据结构课程的个性化资源生成与学习多智能体系统。

后续开发只补齐 A3 比赛差距，不扩展无关业务范围，不修改架构基线，不新增技术方案。
