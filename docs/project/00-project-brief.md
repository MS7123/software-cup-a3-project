# 项目简介

## 项目名称

中国软件杯 A3 参赛项目：基于大模型的个性化资源生成与学习多智能体系统。

## 项目定位

本项目面向大学课程学习场景，构建一个能够围绕学生画像、课程知识库、知识图谱、学习路径、资源生成、测验评价和反馈调整形成闭环的个性化学习系统。

系统不应退化为“上传资料 + AI 聊天”的普通知识库产品。参赛作品的核心竞争点应体现：

- `Multi-Agent` 分工与可解释执行记录。
- 基于学生画像、掌握度和学习路径的 `Personalization`。
- 基于课程资料和知识点关系的 `Knowledge Grounding`。
- 讲义、例题、测验、复习计划等学习资源生成能力。
- 前后端分离、数据库、异步任务、日志、部署与文档的工程完整性。

## 当前阶段

当前仓库已完成 A3 开源项目技术调研和开源合规边界说明。下一阶段进入架构基线、数据模型、API 契约和最小可行闭环设计。

## 已确认 MVP 边界

- 参赛方向：继续做 A3，不切换到 A6。
- 演示课程：数据结构。
- MVP 知识点范围：复杂度分析、链表、栈/队列、二叉树遍历、BFS/DFS。
- 第一阶段用户范围：只做学生端闭环。
- 数据来源：学生画像和课程资料使用模拟数据即可。
- 展示优先级：优先突出 `Multi-Agent` 协作流程，其次展示个性化资源生成质量。
- `Multi-Agent` 展示粒度：展示摘要，不要求展示每个 Agent 的完整输入输出。
- 架构基线：Requirement Agent 不调整已 Accepted 的架构基线，只提供需求侧架构影响分析。

## MVP 闭环范围

第一阶段应围绕数据结构课程完成一个可演示的学生学习闭环：

1. 学生选择或输入数据结构学习目标，范围限定在复杂度分析、链表、栈/队列、二叉树遍历、BFS/DFS。
2. 系统基于模拟学生画像和模拟课程资料识别学习需求。
3. `Planner Agent` 生成阶段化学习路径。
4. `Resource Agent` 生成对应学习资源。
5. `Tutor Agent` 基于课程资料回答学生问题。
6. `Quiz Agent` 生成测验题。
7. `Evaluator Agent` 根据作答结果给出反馈和下一步建议。
8. 系统展示关键 Agent 的输入、输出、调用顺序和决策依据。

## 非目标

- 不直接 fork 或拼接完整开源学习平台。
- 不复制 `AGPL-3.0`、`GPL-3.0` 或无明确 license 项目的核心代码进入参赛主体。
- 第一阶段不引入 `Neo4j`、`OpenSearch`、`Kubernetes`、复杂在线协同编辑器等超出比赛短周期的重型架构。
- 第一阶段不以 `Streamlit` 作为最终参赛工程主形态。
- 第一阶段不做教师端、管理端或真实学校数据接入。
- 第一阶段不把 A6 智慧校园事务流程作为当前产品范围。
