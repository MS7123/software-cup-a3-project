# A6 赛题讨论总结：智慧校园 AI 原生智能体平台

整理日期：2026-06-02  
赛题：A6 - 智慧校园・AI 原生：基于金蝶 AI 苍穹的新质校园智能体创新平台

## 1. 赛题理解

A6 可以理解为：基于金蝶 AI 苍穹平台，开发一个面向高校场景的智慧校园智能体平台。

它不是单纯做一个校园 App，也不是只做一个问答机器人，而是要围绕学生服务、教务管理、辅导员工作、教师教学和行政办公等场景，设计能够理解自然语言、查询知识库、调用业务工具、发起流程并返回业务结果的 AI Agent。

核心目标：

> 用金蝶 AI 苍穹的低代码、流程、知识库、Agent、Skill 等能力，构建一套能够支撑校园事务办理和管理辅助的 AI 原生应用。

## 2. 项目主要内容

推荐项目方向：

> 智校通：基于金蝶 AI 苍穹的学生事务智能体平台

不建议一开始做“全能智慧校园平台”，而应选择 2-4 个闭环完整的校园场景，突出智能体的业务办理能力。

### 2.1 请假审批智能体

学生通过自然语言发起请假请求，例如：

> 我明天上午身体不舒服，想请一天假。

系统应完成：

- 识别请假意图；
- 抽取请假时间、原因、影响课程等信息；
- 自动生成请假申请表；
- 提交辅导员审批流程；
- 支持查询审批状态；
- 审批完成后返回结果。

这个场景适合展示平台的表单、流程、权限和 Agent 工具调用能力。

### 2.2 奖学金申请智能体

学生询问奖学金申请资格，例如：

> 我绩点 3.6，综测排名班级第 5，能申请哪些奖学金？

系统应完成：

- 查询奖学金政策知识库；
- 查询学生成绩、综测排名、处分记录等模拟数据；
- 判断是否满足申请条件；
- 生成材料清单；
- 给出不满足条件的原因；
- 支持发起奖学金申请流程。

这个场景适合展示知识库问答、业务规则判断和流程发起。

### 2.3 培养方案与选课咨询智能体

学生询问培养方案、课程先修关系或毕业要求，例如：

> 我想下学期选软件测试，还需要先修哪些课？

系统应完成：

- 基于培养方案知识库回答问题；
- 查询学生已修课程和成绩；
- 检查课程先修关系；
- 判断毕业要求完成情况；
- 给出补修、选课或学习建议。

这个场景适合展示校园知识库、学生画像和个性化建议。

### 2.4 辅导员工作助手

面向辅导员或班主任，提供班级管理辅助能力：

- 汇总请假申请和审批状态；
- 汇总学生成绩、处分、请假、活动参与等数据；
- 标记潜在学业风险学生；
- 生成谈话建议；
- 生成班级通知；
- 输出学生事务处理看板。

这个场景适合展示管理端价值和数据分析能力。

## 3. 与 A3 的区别

| 维度 | A3 | A6 |
|---|---|---|
| 目标 | 帮学生学得更好 | 帮校园事务和管理更智能 |
| 核心场景 | 个性化学习、资源生成、测验、辅导 | 学生事务、教务流程、行政服务、辅导员工作 |
| 技术重点 | RAG、Multi-Agent、学习路径、资源生成 | 金蝶平台、低代码、流程、权限、Agent、Knowledge Base |
| 开发自由度 | 高，可以自主选择技术栈 | 中，受金蝶平台能力和规则约束 |
| 风险来源 | 自研系统工作量较大 | 平台账号、文档、权限、部署和操作学习成本 |

## 4. 金蝶 AI 苍穹平台可能承担的能力

基于前期讨论，A6 作品应尽量体现这些平台能力：

- 低代码应用开发：配置校园业务对象、表单和页面；
- 业务流程：实现请假、奖学金、报修等审批流；
- 权限与角色：区分学生、辅导员、教师、管理员；
- Knowledge Builder：维护学生手册、培养方案、奖学金政策、请假制度等知识库；
- Agent Builder：创建面向不同角色的智能体；
- Skill Builder：配置智能体可调用的技能，例如查询学生数据、生成申请表、发起流程；
- 数据看板：展示学生事务、审批效率和风险提醒等指标。

## 5. 上手与完成难度

在假设可以拿到金蝶 AI 苍穹账号，并且项目部署在金蝶平台的前提下：

- 上手难度：中高；
- 完成难度：中等到偏高；
- 主要难点不是写代码，而是平台学习、业务建模、流程配置和智能体闭环设计。

### 5.1 主要难点

| 难点 | 具体表现 |
|---|---|
| 平台学习成本 | 需要理解应用、数据对象、表单、流程、权限、知识库、Agent、Skill 等概念 |
| 开发方式变化 | 不能完全按熟悉的前后端方式开发，很多能力需要在平台中配置 |
| 文档依赖强 | 如果没有清晰文档、赛事培训或示例工程，容易卡在平台操作上 |
| 业务建模要求高 | 要把校园事务建模为数据对象、流程、角色和权限 |
| 智能体闭环难 | 智能体不能只回答问题，还要查询、判断、填表、发起流程和反馈状态 |
| 演示依赖平台稳定 | 平台账号、模型额度、网络、租户权限和部署状态都会影响演示 |

### 5.2 平台可能带来的优势

| 平台能力 | 对项目的帮助 |
|---|---|
| 低代码表单 | 减少 CRUD 页面开发工作 |
| 审批流 | 快速实现请假、奖学金、报修等流程 |
| 权限角色 | 支持学生、辅导员、教师、管理员等角色 |
| 知识库 | 快速接入校园制度、培养方案和办事指南 |
| Agent / Skill | 以可视化或半可视化方式配置智能体能力 |
| 部署托管 | 减少服务器部署和运维成本 |

总结：A6 是“前期学平台慢，后期搭业务快”的类型。如果 3 天内能跑通一个小闭环，例如“自然语言请假 -> 自动生成申请 -> 提交审批流程”，就可以继续推进；如果平台环境长期卡住，应谨慎选择。

## 6. 三天可行性验证计划

在正式投入 A6 前，建议先做一个 3 天验证。

### 第 1 天：数据对象与表单

目标：

- 创建学生信息对象；
- 创建请假申请对象；
- 配置学生、辅导员两个角色；
- 做出一个可填写、可查看的请假申请表。

验收标准：

- 能新增学生模拟数据；
- 能提交请假申请记录；
- 不同角色看到的数据范围不同。

### 第 2 天：审批流程

目标：

- 配置请假审批流程；
- 学生提交申请；
- 辅导员审批；
- 学生查询审批状态。

验收标准：

- 流程状态可从“待审批”变为“通过/驳回”；
- 审批记录可查询；
- 基本权限正确。

### 第 3 天：智能体闭环

目标：

- 创建请假智能体；
- 配置自然语言信息抽取；
- 让智能体生成请假申请；
- 尝试发起或辅助发起审批流程。

验收标准：

- 用户用自然语言描述请假需求；
- 智能体能抽取时间、原因、天数等字段；
- 能生成结构化申请数据；
- 能进入审批流程或给出明确的流程入口。

## 7. 可参考的开源项目

这些开源项目不能完全替代金蝶 AI 苍穹，但可以帮助理解其相关能力。

| 项目 | 链接 | 可参考能力 | 备注 |
|---|---|---|---|
| Dify | https://github.com/langgenius/dify | LLM 应用、知识库、RAG、Agent、Workflow、工具调用 | 最适合理解 AI 应用平台 |
| Flowise | https://github.com/FlowiseAI/Flowise | 可视化 LLM workflow、RAG pipeline、聊天机器人 | 适合理解拖拽式 AI 流程 |
| n8n | https://github.com/n8n-io/n8n | 流程自动化、API 调用、触发器、动作 | 适合理解业务流程自动化 |
| Appsmith | https://github.com/appsmithorg/appsmith | 低代码内部工具、后台管理、表单、数据源连接 | 适合理解低代码业务页面 |
| ToolJet | https://github.com/ToolJet/ToolJet | 低代码管理系统、数据源连接、内部应用 | 与 Appsmith 类似 |
| Flowable | https://github.com/flowable/flowable-engine | BPMN 流程、审批流、业务流程建模 | 适合理解流程引擎思想 |
| LangGraph | https://github.com/langchain-ai/langgraph | Agent 状态流转、多智能体编排 | 可参考 Agent 编排思想 |
| CrewAI | https://github.com/crewAIInc/crewAI | 多角色 Agent 协作 | 可参考角色分工 |
| Moodle | https://github.com/moodle/moodle | 教学平台、课程、测验、用户角色 | 更偏教学系统，不是智慧校园事务平台 |

### 7.1 开源项目的使用边界

如果 A6 明确要求部署在金蝶平台，则不应围绕这些开源项目搭建主系统。它们更适合作为：

- 产品功能参考；
- 平台能力理解材料；
- Agent 和 Workflow 设计参考；
- 开源合规说明中的调研来源。

不建议：

- 直接使用开源平台替代金蝶 AI 苍穹；
- 复制开源项目代码作为参赛主体；
- 在最终作品中让开源平台承担核心部署，而金蝶平台只是展示入口。

## 8. 初步判断

A6 适合愿意学习企业低代码平台、业务流程建模和校园事务场景的团队。它的亮点不在于算法深度，而在于：

- 是否真正使用金蝶平台能力；
- 是否有完整校园业务闭环；
- 智能体是否能够办事，而不是只回答；
- 知识库、数据对象、流程和权限是否结合；
- 演示是否能体现“AI 原生智慧校园”的平台化价值。

如果平台账号、赛事文档和示例工程都能顺利获得，A6 是可做的；如果平台环境不稳定或资料不足，风险会明显高于 A3。
