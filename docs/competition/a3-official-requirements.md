# A3 官方赛题要求整理

最后更新：2026-07-12

文档性质：官方要求整理与项目开发解读
官方来源：[A3-基于大模型的个性化资源生成与学习多智能体系统开发](https://www.cnsoftbei.com/content-3-1286-1.html)

## 1. 赛题目标

参赛团队需要围绕**新时代大学生的学习需求和痛点**进行调研，融合**前沿 AI 技术和工具**，开发能够高效生成个性化、多模态学习资源的**智能体系统**。

系统的核心目标是：

1. **提升学生学习效率**。
2. **优化学习资源利用**。
3. **增强学习效果**。

赛题列举的学习资源类型包括资源设计方案、PPT、题库、多模态视频或动画、实操案例、实践项目学习材料等。

## 2. 核心功能要求

### 2.1 对话式学习画像自主构建

系统应当：

- 摒弃传统繁琐表单，支持通过**自然语言对话**构建学生画像。
- 结合学生的**专业、学习目标、学习历史**等信息，自动抽取学生特征。
- 构建不少于**6 个维度**的动态学生画像。
- 支持画像在学习过程中**随学随新**，而不是只在首次填写时生成一次。

赛题给出的画像维度示例包括：

- 知识基础
- 认知风格
- 易错点偏好

这些是示例维度，系统可以根据具体课程和产品设计补充其他维度。

### 2.2 多智能体协同的资源生成

系统必须体现**多智能体（Multi-Agent）架构设计**，不能只提供单一聊天机器人或单一生成流程。

系统应当通过与学生的智能交互，综合使用**大模型、AI 前沿技术和工具**，根据以下信息生成针对性的学习资料：

- 学生专业
- 课程内容
- 知识短板
- 学习需求

不同角色的智能体需要协作完成至少**5 种类型**的个性化资源生成。赛题列举的资源类型包括：

| 资源类型 | 说明 |
|---|---|
| 专业课程讲解文档 | 针对课程知识点生成结构化讲解内容 |
| 知识点思维导图 | 展示知识点之间的层级、关联或先修关系 |
| 不同类型练习题目 | 根据学生水平和薄弱点生成练习、测试或题库 |
| 拓展阅读材料 | 提供与当前知识点相关的补充学习内容 |
| 多模态教学视频或动画 | 以视频、动画或相应的设计方案呈现教学内容 |
| 代码类实操案例 | 面向编程课程或实践内容生成可操作案例 |

上述列表包含**6 类示例资源**，官方要求是至少实现其中**5 类**或等价的个性化资源类型。

### 2.3 个性化学习路径规划和资源推送

系统应依托多智能体协同机制，整合系统生成的个性化资源，并根据大模型对学生状态的分析完成以下工作：

- 分析学生的**专业**。
- 分析学生的**学习进度**。
- 分析学生的**知识掌握情况**。
- 分析学生的**学习偏好**。
- 规划科学、动态的个性化学习路径。
- 明确学习步骤和学习顺序。
- 基于学生画像精准推送学习资源。

资源推送应覆盖多种内容形态，包括：

- 文档
- 视频
- 题库
- 实操案例

### 2.4 智能辅导（可选加分项）

当学生在学习过程中遇到问题时，系统可以提供即时、多模态的答疑解惑服务。

可选能力包括：

- 通过智能体分析学生的问题和学习状态。
- 使用大模型提供知识支持。
- 结合多模态生成技术进行针对性讲解。
- 输出详细的文字解答。
- 输出图解说明。
- 输出短视频讲解。
- 根据学生情况提供学习引导。

### 2.5 学习效果评估（可选加分项）

系统可以实时跟踪以下数据：

- 学习行为
- 练习和测试情况
- 学习资源使用反馈

在此基础上，系统可以使用大模型的数据分析能力完成：

- 对学习效果进行多维度、精准评估。
- 根据评估结果动态调整资源推送策略。
- 根据评估结果动态调整学习计划。
- 持续优化学生的学习方案。

## 3. 官方要求的开发检查表

| 检查项 | 要求级别 | 验收关注点 |
|---|---|---|
| 学习画像构建 | 核心要求 | 是否通过自然语言对话构建，而非仅依赖传统表单 |
| 画像维度 | 核心要求 | 是否不少于 6 个维度 |
| 画像更新 | 核心要求 | 是否支持在学习过程中持续更新 |
| Multi-Agent 架构 | 核心要求 | 是否有不同角色智能体协作，而非单 Agent 串行包装 |
| 个性化资源 | 核心要求 | 是否根据学生专业、课程、短板和需求生成 |
| 资源类型数量 | 核心要求 | 是否至少覆盖 5 种类型 |
| 学习路径 | 核心要求 | 是否包含明确、动态的学习步骤和顺序 |
| 资源推送 | 核心要求 | 是否依据学生画像实现个性化推送 |
| 智能辅导 | 可选加分项 | 是否提供文字、图解或短视频等多模态答疑 |
| 学习效果评估 | 可选加分项 | 是否基于学习行为和测评反馈动态调整方案 |

## 4. 与当前项目的对应关系

本节是基于官方要求和当前仓库代码、文档状态做出的**项目开发解读**，不属于官网原文。

| 官方要求 | 当前项目对应能力 | 当前判断 |
|---|---|---|
| 对话式学习画像 | `POST /api/v1/student-profiles/from-dialogue`、六维画像界面 | 已有可演示实现 |
| 不少于 6 个画像维度 | `learning_goal`、`foundation_level`、`learning_preference`、`available_time`、`weak_points`、`resource_preference` | 已达到数量要求 |
| 画像随学随新 | Quiz 提交后由 Agent trace 触发画像更新 | 已有最小闭环，仍需增强长期学习历史 |
| Multi-Agent 协同 | Planner、Resource、Tutor、Quiz、Evaluator 等角色及 `agent_runs` 记录 | 已有可展示协作链路 |
| 至少 5 类资源 | 讲解文档、练习题、思维导图、拓展阅读、代码实操 | 已达到数量要求 |
| 多模态资源 | 思维导图 SVG、代码案例卡片；视频或动画仍主要是预留方向 | 部分满足，视频/动画生成仍需补强 |
| 个性化学习路径 | `POST /api/v1/learning-paths` 及学习路径页面 | 已有可演示实现 |
| 资源推送 | 基于画像和学习路径展示文档、题库、思维导图、拓展阅读和代码案例 | 已有最小实现 |
| 智能辅导 | Tutor 多轮问答、Markdown 输出、grounded source 展示 | 已实现文字辅导，图解和短视频仍可增强 |
| 学习效果评估 | Quiz、Evaluator、薄弱点反馈和画像更新 | 已有最小实现，掌握度模型仍可增强 |

## 5. 当前开发优先级建议

以下优先级是结合官方要求与当前项目状态得出的**开发建议**：

1. **稳定核心闭环**：画像构建 → 学习路径 → 资源生成 → Tutor → Quiz → Evaluator → 画像更新。
2. **强化 Multi-Agent 证据**：清晰展示角色分工、调用顺序、输入摘要、输出摘要和关键决策。
3. **补强多模态表达**：将视频或动画方向先落实为可演示的教学脚本、分镜或动画方案，再评估真实生成能力。
4. **提升个性化可验证性**：让不同画像、不同薄弱点生成明显不同的学习路径、资源内容和题目难度。
5. **补齐比赛交付材料**：准备赛题对应表、系统开发说明、测试说明、AI Coding 使用说明和演示脚本。

## 6. 需求边界

基于当前项目主线，建议将首版实现范围限定为：

- 以**数据结构课程**作为演示课程。
- 先覆盖复杂度分析、链表、栈/队列、二叉树遍历、BFS/DFS 等核心知识点。
- 聚焦学生端学习闭环。
- 保留真实 LLM 的 opt-in 接入和 rule-based fallback，确保离线演示可运行。
- 将真实视频、动画和图像生成视为后续增强，不把尚未完成的能力表述为已交付。
